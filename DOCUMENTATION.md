## 1. Обзор продукта

**LifeSim: Mayor Mode** — многопользовательский браузерный сервис городской симуляции. Каждый пользователь вводит имя, получает собственный изолированный город с ~1000 агентами-жителями и управляет им в роли мэра: принимает политические решения, следит за ВВП, настроением горожан и тремя метриками репутации в реальном времени.

**Ключевые характеристики:**
- Полностью server-side симуляция — клиент только читает и отправляет команды
- Изолированные инстанции: у каждого игрока независимый город
- Реальное время: тик каждые 60 секунд (= 1 игровой час); 1 игровой день = 24 минуты
- Русский интерфейс по умолчанию с переключением на английский
- Продакшн-адрес: `social-simulate.replit.app`
- Аналитика операторов: `/analytics`

## 3. Архитектура монорепо

```
artifacts/
  api-server/           Express 5, путь /api/*,    порт из $PORT
  mayor-dashboard/      React + Vite UI, путь /
  analytics-dashboard/  Дашборд оператора, путь /analytics
  mockup-sandbox/       Превью UI-компонентов для Canvas

lib/
  db/                   PostgreSQL-схема (Drizzle), composite TS
  api-spec/             OpenAPI YAML + codegen-скрипты
  api-zod/              Сгенерированные Zod-схемы (из OpenAPI)
  api-client-react/     Сгенерированные React Query хуки (из OpenAPI)

scripts/                Утилитные скрипты (leaf package)
```

**Маршрутизация:** глобальный реверс-прокси читает `artifact.toml` каждого артефакта и направляет трафик по путям. Между сервисами и из shell-команд обращаться только через `localhost:80/<path>`, никогда не напрямую по порту.

**Contract-first API:** сначала правится `lib/api-spec/openapi.yaml`, затем запускается codegen:
```bash
pnpm --filter @workspace/api-spec run codegen
```
Это генерирует Zod-схемы в `lib/api-zod` и React Query хуки в `lib/api-client-react`. Сервер использует Zod-схемы для валидации, клиент — сгенерированные хуки.

## 4. Схема базы данных

### Таблицы симуляции

| Таблица | Назначение |
|---|---|
| `players` | Игроки: имя, slug, репутация (3 метрики), деньги мэра, коррупция, game over, victoryReason |
| `agents` | Жители: имя, пол, возраст, деньги, настроение, работодатель, карьерный грейд, характеристики |
| `needs` | 13 потребностей агента (CASCADE от agents, нет playerId) |
| `relations` | Дружеские связи между агентами (двусторонние, 0–100) |
| `businesses` | Предприятия: тип, баланс, статус, кол-во сотрудников |
| `goods` | Товары: цена, количество, спрос, предложение |
| `sim_state` | Состояние симуляции: tick, gameDay, gameHour, бюджет, итоги налогов |
| `sim_config` | Конфигурационные параметры (ключ–значение, unique по playerId+key) |
| `stats_history` | Срезы метрик каждый тик: avgMood, GDP, население, безработица |
| `agent_stat_history` | История отдельных агентов: деньги, настроение, возраст |
| `daily_events` | Карточки ежедневных решений: eventsJson, responded, chosenCardType |
| `event_log` | Постоянный журнал событий города (unique по playerId+eventId) |
| `citizen_requests` | Обращения граждан: имя, район, проблема, категория, статус, стоимость |

**Принципы изоляции:**
- Все таблицы (кроме `needs` и `relations`) имеют колонку `player_id`
- `needs` и `relations` связаны с `agents` через `CASCADE DELETE` — playerId не нужен
- `sim_config` имеет уникальный составной индекс `(player_id, key)` — используется `onConflictDoUpdate`

## 5. Многопользовательский режим

`SimulationManager` — синглтон, хранит `Map<playerId, SimulationEngine>`.

**Жизненный цикл движка:**
1. Игрок делает первый запрос → `getEngine(playerId)` создаёт `SimulationEngine(playerId)` и вызывает `initialize()`
2. `initialize()` загружает из БД: конфиг → состояние → журнал событий → агентов → бизнесы → товары → связи → историю
3. Если агентов нет — генерирует начальную популяцию и запускает симуляцию
4. Иначе — восстанавливает состояние и (если `running=true`) возобновляет таймер

**Slug-based идентификация игрока:**
- Имя "Мэр Иванов" → slug `мэр-иванов`
- Повторный вход по тому же имени — загружает существующий город
- `lastActiveAt` обновляется при каждом входе

## 6. Движок симуляции

Файл: `artifacts/api-server/src/lib/simulation-engine.ts` (~4 400 строк)

### Тайминг

| Параметр | Значение |
|---|---|
| Интервал тика | 60 000 мс (1 минута реального времени) |
| Игровой час | 1 тик |
| Игровой день | 24 тика (24 минуты реального времени) |
| Сохранение в БД | каждые 6 тиков (6 минут) |

### Последовательность шагов одного тика

1. Увеличение `tick`, `gameHour`; при `gameHour === 0` — новый день (`gameDay++`)
2. Пересчёт `maxEmployees` для каждого бизнеса (динамический лимит по балансу)
3. Расчёт индекса экономического благополучия (`wellbeingScore`)
4. Для каждого агента:
   - Деградация потребностей (`needDecayRate`)
   - Покупка еды / товаров (если есть деньги и открытые магазины)
   - Налог с зарплаты
   - Социальные взаимодействия (обновление дружеских связей)
   - Обновление настроения (`mood`) и самочувствия (`wellbeing`)
   - Обновление текущего действия (`currentAction`)
5. Рождаемость и смертность (только в новый день)
6. Иммиграция и эмиграция (только в новый день)
7. Мировые события: 25% шанс при кулдауне ≥ 2 дня (только в новый день)
8. Локальные авто-события: эмиграция, смертность, рождаемость, иммиграция, дефицит бюджета, дисбаланс рынка
9. Периодический отчёт мэра (каждые 3 дня)
10. Обновление производственных цепочек
11. Обновление цен на товары
12. Обновление бизнесов (найм/увольнение, прибыль/убыток, банкротства)
13. Корпоративный налог (1 раз в день с прибыльных бизнесов)
14. Пенсии (1 раз в день пенсионерам)
15. Расходы на государственные услуги (1 раз в день)
16. Обработка отложенных указов мэра
17. Сохранение среза статистики (`stats_history`)
18. Периодическое сохранение состояния в БД
19. Fire-and-forget: генерация обращений граждан

| Атрибут | Тип | Описание |
|---|---|---|
| `name` | string | Русское имя (мужское/женское из словаря) |
| `gender` | m/f | Пол |
| `age` | int | Возраст (18–80 при старте) |
| `money` | float | Сбережения |
| `mood` | float 0–100 | Итоговое настроение |
| `personality` | string | Тип личности: balanced, ambitious, lazy, social, introvert |
| `socialization` | float | Социальная вовлечённость |
| `currentAction` | string | Текущее действие: eating, working, sleeping, socializing, shopping, idle, sick, seeking_job... |
| `employerId` | int/null | ID работодателя (null = безработный) |
| `isRetired` | bool | Пенсионер |
| `careerLevel` | int 1–5 | Грейд: 1=рабочий, 2=специалист, 3=бригадир, 4=менеджер, 5=директор |
| `ambition` | float | Стремление к карьере |
| `strength` | float | Сила (влияет на фермы/мастерские) |
| `intelligence` | float | Интеллект (влияет на школы/больницы) |
| `locationX/Y` | float | Позиция в городе |
| `jobHistory` | JSON | История трудоустройства |
| `jailedUntilTick` | int/null | Только в памяти, сбрасывается при рестарте |

### 13 потребностей (таблица `needs`)

| Потребность | Описание |
|---|---|
| `hunger` | Сытость |
| `comfort` | Комфорт жилья |
| `social` | Социальное общение |
| `health` | Здоровье |
| `sleep` | Сон |
| `education` | Образование |
| `entertainment` | Развлечения |
| `faith` | Духовность |
| `housingSafety` | Безопасность жилья |
| `financialSafety` | Финансовая безопасность |
| `physicalSafety` | Физическая безопасность |
| `socialRating` | Социальный рейтинг |
| `wellbeing` | Общее самочувствие (агрегат) |

Потребности деградируют каждый тик на `needDecayRate` (дефолт: 5 единиц). Восстанавливаются через покупки, работу, социальные взаимодействия и городские сервисы.

### Демография

- **Смертность:** вычисляется по здоровью и возрасту; старше 65 — повышенный шанс
- **Рождаемость:** зависит от `wellbeingScore`, пик у агентов 20–35 лет
- **Иммиграция:** при высоком `wellbeingScore` — притягивает мигрантов
- **Эмиграция:** при низком настроении и безработице — отток жителей
- **Выход на пенсию:** агенты старше 65 при низкой силе/здоровье

### Карьера

- Грейды 1–5, повышение только если в бизнесе есть вакантное место на следующем грейде
- Таблица `STAFFING_TABLE` задаёт лимиты по грейдам для каждого типа бизнеса
- Зарплата зависит от грейда (baseSalary × multiplier)

## 8. Бизнесы и экономика

### Типы бизнесов

| Тип | Категория | Производит | Финансирование |
|---|---|---|---|
| `farm` | Частный | Сырьё (food_raw) | Собственный баланс |
| `workshop` | Частный | Материалы (goods_raw) | Собственный баланс |
| `food` | Частный | Еда (food) | Собственный баланс |
| `service` | Частный | Бытовые товары (service) | Собственный баланс |
| `hospital` | Государственный | Здоровье агентов | Государственный бюджет |
| `school` | Государственный | Образование агентов | Государственный бюджет |
| `park` | Государственный | Развлечения, настроение | Государственный бюджет |
| `temple` | Государственный | Духовность, настроение | Государственный бюджет |

**Стартовый набор:** 80 бизнесов (настраивается через `initialBusinesses`).

### Производственные цепочки

```
farm → food_raw → food store → еда для агентов
workshop → goods_raw → service store → товары для агентов
```

Если фермы или мастерские не производят сырьё — downstream-бизнесы закрываются или снижают производство.

### Динамика найма

- **Частный сектор:** `maxEmployees = max(staffingMin, floor(coef × balance / baseSalary))`
  - farm/workshop: коэффициент 0.08 (низкий оборот)
  - food/service: коэффициент 0.60 (высокий оборот)
- **Государственный сектор:** лимит фиксирован таблицей `STAFFING_TABLE`, финансируется из бюджета

### Банкротства

- Бизнес закрывается при отрицательном балансе после N убыточных тиков
- Экстренный указ мэра (`emergency_bailout`) может спасти банкротящиеся предприятия (один раз на бизнес)
- При закрытии — все сотрудники теряют работу

## 9. Государственный бюджет

| Статья | Направление | Когда |
|---|---|---|
| Подоходный налог | доход | каждый тик (с зарплат занятых) |
| Корпоративный налог | доход | 1 раз в день (5% с прибыльных бизнесов, кроме farm/workshop) |
| Субсидии населению | расход | каждый тик (базовая поддержка бедных) |
| Пенсии | расход | 1 раз в день (pensionRate × baseSalary для пенсионеров) |
| Государственные услуги | расход | 1 раз в день (зарплаты гос. работников) |

**Начальный бюджет:** 10 000 монет.  
**Game over** при бюджете < −50 000.

## 11. Система репутации и условия победы/поражения

### 3 метрики репутации (0–100)

| Метрика | Формула |
|---|---|
| `reputationResidents` | avgMood × 0.5 + (100 − unemployment%) × 0.3 + avgHealth × 0.2 |
| `reputationBusiness` | profitable% × 0.6 + налоговая нагрузка × 0.12 + 20 |
| `reputationGovernment` | budgetScore × 0.5 + (100 − corruption) × 0.3 + 20 |

Метрики обновляются через экспоненциальное сглаживание (α = 0.1, decay = 0.95) при каждом старте симуляции.

### Условия поражения (Game Over)

| Условие | Причина |
|---|---|
| `reputationResidents < 20` | Восстание жителей |
| `governmentBudget < −50 000` | Финансовый крах |
| `mayorCorruption >= 90` | Государственный переворот |

### Условия победы (Victory)

| Условие | Причина |
|---|---|
| `reputationResidents > 80` | Любимчик общества |
| `reputationBusiness > 80` | Деловой правитель |
| `reputationGovernment > 80` | Самый влиятельный |
| `mayorMoney >= 100 000` | Личное обогащение |

При победе игра не заканчивается автоматически — пишется `victoryReason`, игра продолжается.

## 12. Мировые события

Проверяются один раз в день при условии: нет активных длительных событий, кулдаун ≥ 2 дня, шанс 25%, не более 1 мирового события за день.

| Тип | Название | Длительность | Эффект |
|---|---|---|---|
| `good_harvest` | Богатый урожай | 3 дня | фермы производят вдвое больше |
| `bad_harvest` | Неурожай | 3 дня | фермы производят вдвое меньше |
| `wealthy_migration` | Приток богатых мигрантов | мгновенно | +100 богатых жителей (~100 × baseSalary накоплений) |
| `epidemic` | Эпидемия | 5 дней | здоровье деградирует втрое быстрее |
| `economic_boom` | Экономический подъём | 4 дня | все бизнесы ежедневно получают бонус |
| `government_subsidy` | Внешние инвестиции | мгновенно | +грант в бюджет (20 × population монет) |

Не повторяется тот же тип, что был предыдущим.

## 13. Ежедневные события (3 карточки)

Каждый новый игровой день движок проверяет, нужно ли показать 3 карточки-события. Если игрок ещё не ответил в этот день — модальное окно открывается автоматически.

### Генерация карточек

3 карточки соответствуют трём сферам: **Жители / Бизнес / Государство**. Карточка выбирается по текущим метрикам симуляции:

**Жители:**
- безработица > 20% → «Безработица давит на бюджеты семей»
- avgMood < 40 → «Жители жалуются на качество жизни»
- avgHealth < 45 → «В районах фиксируется рост заболеваемости»
- иначе → «В жилых районах растёт бедность»

**Бизнес:**
- убыточных бизнесов > 40% → «Сервисные компании предупреждают о закрытиях»
- дисбаланс спроса/предложения < −0.2 → «Дефицит сырья грозит остановкой производства»
- иначе → «Падение потребительского спроса бьёт по малому бизнесу»

**Государство:**
- бюджет < 20 000 → «Расходы растут быстрее доходов»
- ВВП < 5 000 → «Служба безопасности фиксирует рост напряжённости»
- иначе → «Аналитики рекомендуют повысить эффективность управления»

### Реакции

Для каждой карточки — 3 варианта реакции с разными эффектами:
- изменение бюджета (`budgetChange`)
- изменение репутации (`reputationChanges` по 1–3 метрикам)
- изменение конфига симуляции (`configChanges`)
- длительность эффекта (`durationDays`: 1–3)
- кулдаун (`cooldownDays`)

### Хранение

Карточки сериализуются в JSON и хранятся в `daily_events` (уникальность по `playerId + gameDay`). При повторном запросе того же дня — отдаются из БД без пересчёта.

## 14. Обращения граждан

Файл: `artifacts/api-server/src/lib/citizen-requests.ts`

В конце каждого тика (fire-and-forget) может генерироваться 1–2 обращения гражданина. Вероятность и категория зависят от текущих метрик.

### 6 категорий обращений

| Категория | Примеры проблем |
|---|---|
| `finances` | «Не могу оплатить коммунальные счета», «Семья на грани выживания» |
| `work` | «Остался без работы», «Безработный уже четыре месяца» |
| `food` | «Цены на продукты выросли вдвое», «Дети плохо питаются» |
| `health` | «Нет денег на операцию», «Ребёнок болеет, врач недоступен» |
| `comfort` | «Дороги разбиты», «Мусор не вывозят», «Нет парков» |
| `safety` | «В районе участились кражи», «Нет уличного освещения» |

Взвешенный выбор категории учитывает: бюджет, безработицу, avgMood, avgHealth.

### Интерфейс

В кабинете мэра — 2×2 сетка из 4 кнопок. Кнопка «Обращения граждан» показывает счётчик непрочитанных (badge). При открытии — список обращений с двумя действиями на каждое:

- **Помочь** — списывает `budgetCost` из бюджета, улучшает репутацию жителей на `reputationChange`
- **Отказать** — без затрат, снижает репутацию жителей

### API

| Метод | URL | Описание |
|---|---|---|
| GET | `/api/players/:id/requests` | Список обращений (статус pending) + count |
| POST | `/api/players/:id/requests/:rid/help` | Помочь гражданину |
| POST | `/api/players/:id/requests/:rid/refuse` | Отказать гражданину |

## 15. Журнал событий

Файл: `lib/db/src/schema/simulation.ts` → `eventLogTable`

Журнал хранится в БД (таблица `event_log`) и загружается при инициализации движка. До этого хранился только в памяти и терялся при рестарте — проблема устранена.

### Источники записей

| Источник | Периодичность |
|---|---|
| Мировые события | ~раз в 2–4 дня (25% шанс) |
| Локальные авто-события | до 2 в день (при превышении пороговых значений) |
| Периодический отчёт мэра | каждые 3 игровых дня (гарантированно) |

### Локальные авто-события (пороги)

| Событие | Условие |
|---|---|
| Волна эмиграции | lastEmigrants ≥ max(3, pop × 1%) |
| Повышенная смертность | lastDeaths ≥ max(2, pop × 0.8%) |
| Приток мигрантов | lastImmigrants ≥ max(5, pop × 1.2%) |
| Бэби-бум | lastBirths ≥ max(3, pop × 0.8%) |
| Дефицит бюджета | governmentBudget < −500 |
| Дефицит товаров | demand − supply > pop × 0.5 |
| Перепроизводство | supply − demand > pop × 0.5 |

### Поля записи

`id`, `playerId`, `eventId` (unique), `type`, `name`, `description`, `icon`, `severity` (positive/negative/neutral), `gameDay`, `tick`, `recordedAt`

## 17. Интерфейс игрока

### Экран входа (`/`)

- Текстовое поле «Введите имя администратора»
- Кнопка «Инициализировать город»
- POST `/api/players` → ID сохраняется в `localStorage` → редирект на дашборд

### Дашборд (`/dashboard` или `/?id=...`)

Данные опрашиваются каждые 3 секунды через React Query.

#### Шапка (Header)

- Название `LIFESIM` + имя игрока
- Тикающие часы: `ДЕНЬ X / ЧАС Y / бюджет ₽...`
- Статус: `● РАБОТАЕТ` / `○ ПАУЗА` (badge)
- Кнопки: `📜 Указы мэра`, `⚙ Параметры`, переключатель языка, выход

#### KPI-строка (5 плиток с мини-графиками)

| Метрика | Отображение |
|---|---|
| Население | число жителей + спарклайн |
| Ср. настроение | X / 100 + спарклайн (синий) |
| ВВП | сумма в монетах + спарклайн (зелёный) |
| Безработица | % + число людей (красный при > 20%) + спарклайн |
| Ср. богатство | монеты на жителя + спарклайн (жёлтый) |

Спарклайны: буфер 24 точки, обновляются при каждом рефетче.

#### Левая панель (сайдбар 260px)

**Репутация мэра:**
- 3 прогресс-бара (Жители / Бизнес / Власть), цветовые зоны:
  - < 40 — красный
  - 40–70 — жёлтый
  - > 70 — зелёный

**Кабинет мэра (2×2 кнопки):**
- `📋 Ежедневные события` — открывает модальное окно карточек
- `📬 Обращения граждан` — список обращений (badge с непрочитанными)
- `💰 Личные средства` — деньги мэра и уровень коррупции
- (4-я кнопка — свободная зона)

**Сводка по городу:**
- Здоровье / Сон / Рождаемость-смертность / Миграция
- Бизнесы: % прибыльных, % занятых мест
- Рынок: самый востребованный товар
- Отличились: богатейший / счастливейший житель

**Журнал событий** (сворачиваемый):
- По умолчанию свёрнут (показывает количество записей)
- Развёрнут: первые 5 записей, кнопка «Показать всё» до 30
- Цветовая индикация строк: зелёный/красный/нейтральный

#### Главная область (правая часть)

**Изометрическая карта города** (`CityMapCanvas`):
- Canvas-рендер 560×400 (или адаптивный)
- Отображает бизнесы разными символами по типу
- Анимированные агенты двигаются по случайным траекториям
- Иконки активных мировых событий поверх

**Статистика агентов** (таблица/список):
- Постраничный список с сортировкой и фильтрацией
- Клик на агента → детали: потребности, история работы, дружеские связи

**График истории метрик:**
- Линейный график последних 50 тиков
- Метрики: avgMood, GDP, population, unemploymentRate, governmentBudget

### Модальное окно «Указы мэра»

- 15 карточек указов, разбитых по категориям (social/economy/business/state/personal)
- Каждая карточка: название, описание, стоимость, эффекты, побочные эффекты, задержка
- Кнопка «Издать» → POST `/api/players/:id/mayor/action` → toast с результатом

### Модальное окно «Ежедневные события»

- Открывается автоматически при смене дня (если игрок ещё не ответил)
- Сводка дня (текстовая)
- 3 карточки: Жители / Бизнес / Государство
- Клик на карточку — раскрывает 3 варианта реакции
- Выбор реакции → POST `.../daily-events/respond` → эффекты применяются
- После ответа — кнопка закрыть

### Модальное окно «Обращения граждан»

- Список обращений: имя жителя, возраст, район, проблема, категория
- Кнопки «Помочь» (стоимость ₽) и «Отказать»
- Обновление каждые 10 секунд

### Баннер Game Over / Victory

- Красная полоса во всю ширину шапки с причиной завершения
- Симуляция останавливается, кнопки управления недоступны

## 21. Известные особенности и ограничения

| Проблема | Описание | Статус |
|---|---|---|
| Отложенные указы в памяти | `pendingActions` не персистируются в БД — теряются при рестарте сервера | Известно |
| `activeEvents` в памяти | Список активных мировых событий не сохраняется в БД | Известно |
| `jailedUntilTick` в памяти | Состояние «под стражей» агента сбрасывается при рестарте | По дизайну |
| Игровое время не реальное | Тик = 1 минута реального времени, но симуляция продолжается пока сервер активен | По дизайну |
| Нет WebSocket | Фронтенд опрашивает API каждые 3 секунды (polling), а не push | Known limitation |
| Одна инстанция сервера | При горизонтальном масштабировании `SimulationManager` (Map в памяти) потребует Redis или shared state | Архитектурное |
| Корпоративный налог не с farm/workshop | Фермы и мастерские освобождены от корпоративного налога — они зависят от B2B-дохода | По дизайну |
